# 公開までにやること

対象: 「とにかく売れたい中華料理屋」1チャンネル専用ツールとしての一般公開。

順序は「許諾を取る → 構造を直す → 公開」。断られたら以降の作業が無駄になるので、まず許諾から。

---

## 1. 許諾（最優先）

`連絡文の下書き.md` を参照。

相談時にデモを見せられる状態は必要なので、**限定公開での設置だけは先にやってよい**。Netlify のパスワード保護か Vercel の Preview URL が扱いやすい。

---

## 2. 編集モードの扱い（実装済み）

食材の編集UIは、URL に `?edit=1` が付いているときだけ表示される。

```
http://localhost:3000/?edit=1     ← 自分が編集するとき
http://localhost:3000/            ← 一般ユーザーが見る画面
```

これは隠しているだけで、セキュリティ対策ではない。ただし**編集内容の保存先は各自のブラウザと手元のファイルだけで、サーバーへ書き込む経路が存在しない**。だから第三者が `?edit=1` に気づいて編集しても、他のユーザーやサーバー上のデータには影響しない。

将来サーバー側に保存する形（編集を共有するなど）にする場合は、本物の認証が必要になる。

### 編集から公開までの流れ

1. `?edit=1` で開いて食材を編集する（localStorage に随時保存される）
2. サイドバーの「ingredients.json に保存する」を押す
   - 初回だけ保存先フォルダ（index.html があるフォルダ）を選ぶ
   - 2回目以降はボタン一発で上書きされる
   - Chrome / Edge 以外ではダウンロードになるので、手でフォルダに置く
3. `git add ingredients.json && git commit && git push`
4. Netlify / Vercel が自動でデプロイし、ユーザーに反映される

未保存の変更があるまま閉じようとすると確認が出る。

## 3. 30日ルールへの対応（必須）

YouTube API Services の Developer Policies では、保存した動画のタイトル・説明文・作成者名などを **30日以内に更新または削除**しなければならない。手動実行では要件を満たせないので、定期実行を仕組みに載せる。

`.github/workflows/update.yml` を作る。

```yaml
name: update videos.json
on:
  schedule:
    - cron: '0 18 * * *'   # 毎日 03:00 JST
  workflow_dispatch:

permissions:
  contents: write

jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: node fetch-videos.mjs
        env:
          YOUTUBE_API_KEY: ${{ secrets.YOUTUBE_API_KEY }}
      - run: node build-draft.mjs
      - run: |
          git config user.name github-actions
          git config user.email github-actions@github.com
          git add videos.json ingredients.json
          git diff --staged --quiet || git commit -m "update videos.json"
          git push
```

APIキーは GitHub の **Settings → Secrets and variables → Actions** に `YOUTUBE_API_KEY` として登録する。リポジトリに直接書かない（`.gitignore` で `apikey.txt` を除外済み）。

`build-draft.mjs` を続けて実行しているのは、新しい動画の食材の下書きを自動で作るため。既存の登録は壊さず、空の分量だけを補う動作になっている。

## 4. 概要欄の全文表示をやめる（必須）

閲覧モードでは材料の表と概要欄を表示している。材料リストは事実の羅列に近く保護は薄いが、手順や本文は運営者の表現物。また YouTube の方針上、APIを使って YouTube の代替となるサービスを作ることは認められていない。

**変更内容:**

- 閲覧モードの概要欄を、全文ではなく抜粋に変える
- 「YouTubeで見る」への導線を今より目立たせる
- 「詳しくは動画の概要欄へ」という案内を置く

編集モードでは全文が必要なので、`EDIT` で分岐させる。

---

## 5. 公開に伴って必要になるもの

- **プライバシーポリシー** — アクセス解析や広告を入れるなら必須
- **利用規約** — 免責事項を含む
- **問い合わせ先** — 削除依頼を受け付ける窓口。運営者への約束として必要
- **出典表記** — データの出所がチャンネルであることの明示

---

## 6. ホスティング

| 候補 | 向いている点 |
|---|---|
| Vercel | GitHub連携が楽。Preview URL が相談用のデモに使える |
| Netlify | パスワード保護が簡単。Git なしのドラッグ公開もできる |
| GitHub Pages | 無料。Cron は Actions 側で組む |

---

## 7. PWA化（任意・公開後でよい）

`manifest.json` と service worker の追加だけ。アプリ本体の作り直しは不要。実際に使われてから判断で十分。

---

## やらないこと

- **ネイティブアプリ化** — ストア審査で権利面を突かれ、更新のたびに再審査。得るものがない
- **任意チャンネル対応** — クォータ増枠の監査が必要になる。1チャンネル専用なら不要
- **訪問者ごとのAPI呼び出し** — 定期取得したJSONを配信する形なら、利用者が増えてもAPI消費は1日21ユニットのまま。無料枠（10,000）で十分
