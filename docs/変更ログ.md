## 2026-08-13〜17 のセッション

### 1. 調味料の分量を外す運用をやめる

これまで編集モードで、調味料は分量を手で空にしていた。買い物リストでの除外は
`DEFAULT_PANTRY`（常備品リスト、名前ベース）で行われており、分量の有無とは無関係と
判明したため、分量は空にせず概要欄から拾えたものをそのまま残す運用に変更。

### 2. ingredients.json を作り直し（build-draft.mjs --force）

284本中126本を概要欄から再パース。このとき **分量の一部を誤って消してしまった**
（下記4番で修正）。

### 3. 表記ゆれ辞書の修正（`parse-ingredients.mjs` の `SYNONYM_GROUPS`、および
`ingredients.json` の `aliases`）

- 「ねぎ」を「長ねぎ」に統合（このチャンネルでは「ねぎ」＝長ねぎとして扱う運用）
- にんいく（誤字）→ にんにく
- 片栗 → 片栗粉
- 豆豉醬／豆豉醤 → 豆豉（新規グループ）
- 醬油（異体字）→ 醤油。`normalizeIngredientName` に「醬→醤」の文字レベル正規化を追加
  したので、他の食材名に出てくる「醬」も自動的に揃うようになった
- `test-parser.mjs` にテストケースを追加（92件成功）

### 4. 分量が名前に混入していたデータの修正

「にんにく2カケ」のように分量が食材名にくっついたまま残っていたもの、29件を個別に
修正。加えて、上記2番の再生成で **本来入っていた分量が空になっていたもの15件**
（ヨーグルトソース、肉の下味、卵の下味、水飴タレ、牛乳たね、にんじんアチャール、
ソース×2、黒酢タレ、ニンニクタレ、かける用の油、パスタ茹で塩分濃度、
youki甜麺醤小さい瓶のもの、塩肉の総量の1%）を元の値に復元した。

**未対応（判断が必要）:**
- 一味唐辛子（動画 ZKhDQj8HeeA）: 名前に「小さじ1」、分量欄に「1/2」と数字が2つ残っている
- アサリ（動画 8w3XuvgjeZI）: 名前に「100g」、分量欄に「150gほど」
- 醤油（動画 DRU9SOoKDpk、「もう辞められない」の回）: 合わせタレの「醤油 大さじ1」と
  下味の「醤油 小さじ2」が、醬油の異体字統合で同じ名前になり片方だけが残っている
  （1食材1行のデータ構造では両方を残せない）
- 黒胡椒15カリカリ（動画 jxVuLNy3b8M）: 意味が取れない分量表記
- 動画で使った材料⇩（動画 8w3XuvgjeZI）: 見出しの誤検出。食材ではない
- 外国産牛肩ロース肉400gほど2~2:5cmくらい（動画 paz7MtpXghM）: 分量とサイズが名前に
  混入した壊れたデータ

さらに、名前に数字が残っている項目を全体スキャンすると、調理時間や温度の指示文が
食材として誤検出されているケースが十数件見つかっている（例:「油は170度〜180度で」
「10分〜15分ほど煮込む」）。未着手。

### 5. 野菜のグラム表記を個数表記へ変換

`unitWeights`（概要欄の「1個（200g）」のような記載から集めた換算表）を使って、
玉ねぎ・もやし・ニラ・豆腐・絹豆腐・長ねぎのグラム表記のうち、変換結果が
きれいな個数・分数になるものだけ個数表記に変換（11件）。

変換すると 0.2個・0.4本・0.9丁 のような半端な小数になるものは、買い物の役に立たない
（0本 のようにゼロに丸まって誤解を招くこともある）ため g のまま残した（10件）。
半端で残っている食材と動画IDは Claude 側の作業ログに一覧がある。

あわせて `unitWeights` の中の壊れたエントリを削除:
- 「ネギ青み」: 単位が「−3本」という壊れた値だった（元は「1-3本」の誤パース）
- 「ピーマン」: 1個=20gという明らかに軽すぎる値だった（信頼できるサンプルではない）

**訂正（同日）:** 豆腐・もやしはグラム表記のままでよいとのことなので、この2つの変換は
取り消した（絹豆腐 1丁 → 300g、もやし 1袋・1/4袋 → 250g・60g に戻す）。
`unitWeights` からも「豆腐|丁」「絹豆腐|丁」「もやし|袋」を削除済み。

**注意:** `build-draft.mjs` の unitWeights 収集ロジックにはこの2つを除外する仕組みが
まだ無いので、次に `build-draft.mjs` を実行すると概要欄の記載から再び自動追加される
可能性がある。恒久的に除外したい場合はコード側の対応が必要（未着手）。
